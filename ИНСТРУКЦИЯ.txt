# CorrectSimulator — Инструкция по использованию

Генерация синтетических датасетов сенсорных данных мультикоптера в
симуляторе Microsoft AirSim. Формат данных — EuRoC-совместимый.

Сборка на основе сравнения двух симуляторов (`C:\АО ИТТ\comparison.md`):
взято лучшее из `AirSimDatasetCreator` и `ModelingSystem-1.1`, устранены
выявленные недостатки (см. раздел 11).

## 5. Система координат

AirSim работает в **NED**: X=север, Y=восток, Z=вниз.

### 5.1 Команды траекторий — чистый NED

Все координаты и скорости в `trajectories/*.json` задаются **в NED без
перестановок** и передаются в AirSim как есть (`moveByVelocityAsync(vx, vy, vz)`,
`moveToPositionAsync(x, y, z)`). Поля JSON однозначны и не требуют
перекодировки.

Единственное исключение: перед мировой командой `velocity` нос дрона
доворачивается на курс движения `rotateToYawAsync(atan2(vy, vx))`, чтобы
камера смотрела вперёд (`TrajectoryExecuter.py:106`). Это устраняет
проблему «полёта боком» (стартовый yaw ≈50.6° в LandscapeMountains).

### 5.2 Данные датчиков — единая СК F

Выходная СК датасета — **F = (X=север, Y=вверх, Z=восток)** — поворот NED
на 90° вокруг оси X. Перевод выполняется ТОЛЬКО в `SensorRecorder`, в одном
месте:

- векторы (позиция, скорость, IMU, GPS): `(x, -z, y)` (`SensorRecorder.py:36`)
- кватернион: `q_F = q_R ⊗ q_NED`, где `q_R = (1/√2, 1/√2, 0, 0)` —
  поворот на 90° вокруг X (`SensorRecorder.py:44`). Это математически
  корректная смена базиса (не перестановка компонент).
- углы Эйлера считаются **от сырого (NED) кватерниона** AirSim
  (`SensorRecorder.py:92`) — только они дают физические углы:
  крен/тангаж относительно горизонта, курс от севера. Довёрнутый
  `q_F` записывается только в `state_ground_truth0`.

Примечание о зависании: в покое показания `ay ≈ +9.81` — ось Y в СК F
направлена вверх.

### 5.3 Ground truth

Используется `simGetGroundTruthKinematics()` (`SensorRecorder.py:99`) —
**истинная кинематика симулятора**, а не оценка полётного контроллера
(`kinematics_estimated`). Время берётся из `getMultirotorState().timestamp`.

## 6. Формат данных

### Разделитель

Значения разделены **табуляцией** (`\t`).

### Привязка ко времени

Первая колонка во всех файлах — `time_s` (секунды с момента запуска
записи, единая шкала). Вторая колонка — `timestamp_ns` (внутренний
таймстамп AirSim в наносекундах).

### Структура датасета

```
dataset/
└── mav_{id}/
    ├── imu.dat                  — time_s\ttimestamp_ns\twx\twy\twz\tax\tay\taz
    ├── gps.dat                  — time_s\ttimestamp_ns\tlat\tlon\talt\tvx\tvy\tvz
    ├── angle.dat                — time_s\ttimestamp_ns\troll\tpitch\tyaw
    ├── state_ground_truth0/
    │   └── data.dat             — time_s\ttimestamp_ns\tpx\tpy\tpz\tqw\tqx\tqy\tqz\tvx\tvy\tvz
    ├── cam0/
    │   ├── data/*.png           — левая стереокамера (вперёд)
    │   └── data.dat             — time_s\ttimestamp_ns\tfilename
    └── cam1/
        ├── data/*.png           — правая стереокамера (вперёд)
        └── data.dat             — time_s\ttimestamp_ns\tfilename
```

Данные IMU, СНС и эталонные углы пишутся в плоские файлы `imu.dat`,
`gps.dat`, `angle.dat` в корне датасета. Все `data.dat` содержат строку
заголовка `# time_s\ttimestamp_ns\t...`.

Рядом с датасетом сохраняется лог команд:
`dataset/trajectory_commands_mav_{id}.txt`.

### Частоты записи

| Сенсор | Частота | Поток |
|--------|---------|-------|
| IMU | 200 Гц | фоновый цикл `start_recording(hz=200)` |
| GPS | до 200 Гц | фоновый цикл (обновления координат от симулятора ~10 Гц) |
| Ground truth | 200 Гц | фоновый цикл |
| Стереокамеры cam0/cam1 | цель 20 Гц | основной поток `_sleep_with_recording` |

## 8. Поддерживаемые команды

| Тип | Параметры | Описание |
|-----|-----------|----------|
| `takeoff` | timeout_sec | Взлёт |
| `land` | timeout_sec | Посадка |
| `hover` | duration | Зависание |
| `velocity` | vx, vy, vz, duration | Движение со скоростью (мировая СК, NED); нос доворачивается на курс |
| `velocity_body` | vx, vy, vz, duration | Движение со скоростью (СК дрона) |

| `yaw_to` | yaw | Поворот на заданный угол |
| `path` | path, velocity | Полёт по списку точек |

## 10. Частые ошибки

- **Нет соединения с симулятором** — запущен ли `LandscapeMountains.exe`,
  совпадает ли порт (`41451`) в `IP.py` и `settings.json`.
- **Пустые изображения камер** — имена камер в `settings.json` должны быть
  `cam0`/`cam1`; `settings.json` должен лежать рядом с `.exe` симулятора.
- **Дрон улетает боком** — в старых траекториях не было команды доворота;
  в этом симуляторе нос выравнивается автоматически перед `velocity`.
- **gps.dat пуст** — `gps.is_valid` вернёт False, если GPS отключён
  в `settings.json`; должен быть `"Gps": { "Enabled": true }`.
- **Привязка времени разъехалась** — все файлы пишутся с единой шкалой
  `time_s`, но `timestamp_ns` разных сенсоров отличаются; используйте
  `time_s` для синхронизации.

## 11. Что исправлено относительно исходных симуляторов

Сравнение двух исходных систем — в `C:\АО ИТТ\comparison.md`.

| Проблема | Было | Стало |
|----------|------|-------|
| Кватернион при смене СК | перестановка компонент `(w, x, −z, y)` (ModelingSystem) — неверный крен | `q_F = q_R ⊗ q_NED`, `q_R = (1/√2, 1/√2, 0, 0)` |
| Конверсия координат | размазана по 3 файлам, конфликт полей JSON | только в `SensorRecorder`; команды — чистый NED |
| Курс дрона | не управлялся (полёт боком) | `rotateToYawAsync(atan2(vy, vx))` перед `velocity` |
| Ground truth | `kinematics_estimated` (оценка контроллера) | `simGetGroundTruthKinematics()` — истинная GT |
| Углы Эйлера | отдельная папка `state_groundtruth_euler0` | плоский `angle.dat` в корне; считаются **от сырого (NED) кватерниона** — физические углы (крен/тангаж от горизонта, курс от севера) |
| Папка GT | `state_groundtruth_estimate0` | `state_ground_truth0` (истинная GT) |
